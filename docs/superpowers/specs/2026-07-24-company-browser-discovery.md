# 公司招聘浏览器检索规格

## 目标

针对公司清单，使用 Playwright 在公开搜索结果中发现招聘入口，并将候选分为：

- `OFFICIAL_CANDIDATE`：可交由现有确定性验证引擎判定的官网招聘候选；
- `LEAD_ONLY`：公司主体匹配、但仅来自第三方招聘平台或未能验证为官网的投递线索；
- `REJECTED`：广告、新闻转载、高校就业网、培训机构、无关主业务页或不安全链接。

该能力只产出带证据的发现结果。官网真实性、职业门户验证、岗位提取和 SQLite 写入仍由现有链路负责；不得将 `LEAD_ONLY` 升格为 `VERIFIED`。

## 输入与输出

输入是一组公司记录，至少有 `company`；可选 `officialDomain`、`market` 与别名。每家公司使用固定查询：`<company> 招聘`，必要时追加 `校招`、`实习` 或用户指定的招聘类型。

浏览器发现输出两份 JSON：

- `candidates.json`：标准手工候选结构，供现有 `lite-job-search search --manual` 验证；
- `leads.json`：第三方线索，包含公司名称、平台、URL、标题、搜索查询、搜索排名、页面证据和 `classification: "LEAD_ONLY"`。

所有结果都带 `discoveryMethod: "playwright_search"`、时间戳、原始搜索标题/摘要和分类理由。浏览器不可启动、搜索不可达、出现验证码/登录墙、或页面读取失败时，写入每家公司 `FAILED` / `BLOCKED` 原因；不得以空结果表示成功。

## 搜索结果与候选分类

1. 仅读取可见自然搜索结果；结果 DOM 标记为广告、推广、赞助或新闻时直接拒绝。
2. 对候选 URL 做公共 HTTP(S) 与去重检查。
3. 公司主业务首页是弱线索，默认不作为招聘候选。品牌招聘子域名或路径（例如 `job.xiaohongshu.com`、`/career`、`/jobs`、`/recruit`、`/social`、`/campus`）才可成为 `OFFICIAL_CANDIDATE`。
4. 发现与公司主体匹配的招聘平台页（例如猎聘、BOSS）时，输出 `LEAD_ONLY`，不传入官网验证成功统计。
5. 新闻、转载、学校就业网、培训页与不匹配主体的第三方页均为 `REJECTED`，保留理由但不输出为可投递线索。

## 页面下钻

浏览器访问官网候选后，按可见文本和 URL 发现招聘导航链接：`社会招聘`、`校园招聘`、`实习`、`应届生`、`岗位列表`、`职位`、`Jobs`、`Careers`。

- 列表页或详情页有岗位卡片/岗位详情结构时，保留为更深的官网候选。
- 招聘入口或活动选择页本身没有岗位时，继续下钻一层，分别记录各招聘类型的页面与状态。
- 空列表必须记录 `NO_OPENINGS`，并带页面 URL 与可见空态证据；不得把同一公司的实习开放推论为校招全职开放。
- 登录、验证码、访问限制不会被绕过；记录 `BLOCKED`。

## 集成边界

第一版采用一个独立的非核心脚本及测试夹具，不改变：

- `engine/upstream/providers/**`；
- 既有 Search Provider contract；
- 核心域模型、SQLite schema、验证评分规则；
- 既有 CLI 命令的参数和默认行为。

脚本只调用 Playwright 与已有公共 URL guard；它通过文件契约将 `OFFICIAL_CANDIDATE` 交给既有验证 CLI。将来若需要一条命令自动编排，必须另行评审 adapter 与 CLI 设计。

## 验收标准

- 含推广、新闻和主业务首页的固定搜索结果中，只输出符合规则的官网候选与 `LEAD_ONLY`。
- 小红书式招聘子域名会成为官网候选，主站首页不会单独成为可验证招聘入口。
- 4399 式校园入口可下钻并区分实习与应届生状态。
- 猎聘公司主体页被输出为 `LEAD_ONLY`，不计为官网候选或官网验证成功。
- 浏览器/网络/访问限制均有逐公司失败原因，且测试不依赖真实搜索引擎。
