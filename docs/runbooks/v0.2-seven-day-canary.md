# LJS v0.2 固定公司池七日 Canary 手册

本手册用于验证“已确认招聘入口增量监控”是否能稳定运行。七日结果必须来自真实运行，
不能用单元测试、模拟 HTML 或一次性成功替代。

## 运行边界

- 只选择已经通过确定性验证的 `VERIFIED` 招聘入口。
- 已知入口监控不调用搜索引擎，也不自动启动浏览器。
- `401`、`403`、`429`、验证码或访问挑战记录为 `BLOCKED`，不推断为无招聘。
- 只有页面明确出现“暂无岗位”等语义时才记录 `NO_OPENINGS`。
- 单次失败或单次岗位缺失不能关闭历史岗位。
- 第三方招聘平台继续只进入候选/审核，不进入学生正式投递表。

## 首次准备

```powershell
Copy-Item -LiteralPath data/lite-job-search.sqlite `
  -Destination data/lite-job-search.pre-v0.2-canary.sqlite
npm.cmd run monitor:network:prepare -- --target-count 100
npm.cmd run audit:cn-ats
```

检查 `output/monitoring-network/plan.json`，确认 `PORTAL_MONITOR` 中只包含已经核验的官方
招聘站、官方 ATS 或官方公众号入口。搜索 Circuit 即使处于 `OPEN`，这些任务也必须保持
`runnable: true`。

## 每日执行

```powershell
npm.cmd run monitor:endpoints -- --target-count 100
```

- `output/monitoring-network/known-endpoint-monitor-report.json`

本地看板的“招聘入口监控网络”区域显示端点、观测、岗位版本变化和四类队列数量。
`GET /api/monitoring-network?limit=500` 可用于审计明细。

## 验收指标

- 七日内搜索引擎熔断没有阻塞 `PORTAL_MONITOR`。
- 相同页面可以稳定记录为 `NOT_MODIFIED`，且不重复解析。
- 每个失败入口都保留原因、时间和来源 URL。
- 未出现一次网络失败导致岗位被错误关闭的案例。
- 新增或变化岗位有 `JobRevision`；岗位总量与学生正式发布量保持分离。
- SQLite 迁移可在备份副本上重复执行。

## 停止与回滚

出现数据库写入错误、公司归属串线或大量错误关闭时立即停止 Canary。保留失败数据库和
报告，不覆盖证据。需要回滚时先关闭所有 LJS 进程，再用首次准备时创建的副本恢复；不要
在浏览器安全验证期间增加并发、切换 Profile 或尝试绕过访问控制。
