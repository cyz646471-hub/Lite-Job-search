# LJS v0.2 招聘入口增量监控网络

状态：已批准开发
版本目标：`0.2.0`
产品依据：`Career PF 招聘机会发现与验证系统 LJS PRD V1.0`

## 目标

v0.2 将 LJS 的生产重心从“逐家公司调用搜索引擎并使用浏览器检索”调整为：

> 招聘入口知识库 + 已知入口增量监控 + 公开信号发现 + 搜索引擎低频补洞 + 用户反馈闭环。

本版本不修改现有 Provider Contract、Verification Engine 的官网真实性权限或现有 CLI
参数语义。搜索结果、第三方招聘平台、高校转载、新闻和聚合页继续只作为发现证据，
不能成为学生正式投递入口。

## 生产数据流

```text
MonitorTask / 固定公司池
        |
        v
Coverage Planner
        |
        +-- PORTAL_MONITOR
        |      已核验官网、ATS、公开 JSON、Sitemap
        |
        +-- PORTAL_RECOVERY
        |      已知入口失效、重定向、解析器失败
        |
        +-- MARKET_DISCOVERY
        |      新公司、未知入口、低频搜索补洞
        |
        +-- REVIEW_FEEDBACK
               审核任务、用户失效反馈、规则学习
        |
        v
SourceEndpoint -> FetchObservation -> Verification Engine
        |
        v
RecruitmentEvent -> JobOpening -> JobRevision
        |
        v
A/B/C 发布门禁 -> ReviewTask -> 岗位分配与 UserAction
```

## 调度原则

- `PORTAL_MONITOR` 不依赖搜索引擎，搜索 Circuit 打开时仍可运行。
- `PORTAL_RECOVERY` 先尝试普通 HTTP、ATS Adapter 和已知官方导航，再决定是否使用浏览器。
- `MARKET_DISCOVERY` 才允许使用显式选择的搜索引擎；Circuit 打开时记录
  `DEFERRED`，不阻塞其他队列。
- `REVIEW_FEEDBACK` 根据开放审核任务和 `REPORT_INVALID` 等用户行为安排复检。
- 浏览器始终是兜底通道，不通过新 Profile、切换引擎或并发来规避访问控制。

建议生产资源配比为：已知入口监控 70%、公开招聘信号 20%、搜索补洞 10%。这是调度
默认值，不是数据质量验收指标。

## 新增数据实体

### SourceEndpoint

表示可重复监控的公开招聘数据端点。它可以是公司级招聘目录、ATS 租户、公开 JSON、
Sitemap、静态招聘页或官方公众号入口。它不替代 `CareerPortal`：

- `CareerPortal` 保存公司归属和官方验证结论；
- `SourceEndpoint` 保存访问方式、Adapter、检查频率和运行状态。

### FetchObservation

保存一次端点检查的事实，包括 HTTP 状态、最终 URL、内容与结构哈希、页面角色、岗位
数量、招聘可用状态、失败原因和证据。网络失败、阻断和解析失败不能写成空岗位结果。

### JobRevision

保存岗位首次发现、更新、再次出现、缺失、关闭和重新开放的版本事实。`JobOpening`
继续作为当前投影。单次抓取失败不关闭岗位。

### MonitorPolicy

保存公司、招聘入口或端点的监控队列、优先级、频率、浏览器/搜索权限和连续缺失阈值。
招聘季、用户关注、历史产出和失败类型可以改变下次检查时间。

## 国内 ATS 优先级

v0.2 不使用固定的北美 ATS 顺序决定中国市场开发优先级。系统从 SQLite 中统计当前活跃
招聘入口域名和 ATS 类型，再按“已核验公司覆盖数、入口数、开放招聘数”排序。

首批重点包括现有数据中可识别的 Moka、北森/Zhiye/iTalent、飞书招聘、Hotjob、
Moseeker，以及高频企业自建 SPA/API。Workday、Greenhouse、Lever、
SmartRecruiters 等继续服务在华外企。

## v0.2 验收条件

- 新迁移可在旧数据库上幂等执行，并可以从备份恢复。
- 已核验招聘入口自动登记为 `SourceEndpoint`。
- 每次增量检查可以保存 `FetchObservation`，相同内容可识别为未变化。
- 岗位更新写入 `JobRevision`；一次失败不会错误关闭岗位。
- 四类队列可以独立生成，搜索 Circuit 只推迟 `MARKET_DISCOVERY`。
- 固定池计划优先处理已核验端点，不重新全网搜索。
- 看板能分别显示可监控端点、成功观测、变化岗位和各队列数量。
- 所有新增规则具备自动化测试；完整测试套件通过。
- 提供 7 天固定池 Canary 的运行手册和验收模板，但发布代码时不伪造七天结果。
