# LJS v0.3 中国 ATS 与事实观测网络

## 范围

本版本补齐 Moka、北森/Zhiye/iTalent、飞书招聘、Hotjob、Moseeker 与当前
数据库中实际产出岗位的企业自建站。适配器只负责页面解析，官网归属仍由
确定性 Verification Engine 决定。

## 事实模型

- `SourceEndpoint`：实际监控 URL、类型、Adapter、频率、ETag、
  Last-Modified、最近成功/失败、HTTP 状态和下次检查时间。
- `FetchObservation`：每次检查的 HTTP、最终 URL、内容/结构哈希、页面
  角色、岗位数、失败原因与证据。
- `PageSnapshot`：原始正文文件、字节数、内容类型和哈希，可用
  `npm run monitor:snapshot:replay -- --snapshot-id <id>` 离线重放。
- `JobOpening`：当前岗位投影。
- `JobRevision`：发现、更新、缺失、关闭与重开历史。
- `MonitorPolicy`：队列、频率、优先级、学生关注/历史投递信号和连续缺失
  阈值。

失败、受阻和 `304 Not Modified` 均不会增加岗位缺失次数。只有新的成功
快照或明确的关闭证据参与状态变更；默认连续 3 次成功检查均未出现才关闭。

## 调度

- `PORTAL_MONITOR` 不使用搜索引擎，优先条件 HTTP/ATS。
- `PORTAL_RECOVERY` 处理失败、跳转和解析器失效，可在不绕过访问控制的
  前提下使用浏览器兜底。
- `MARKET_DISCOVERY` 才使用搜索引擎；搜索 Circuit 只暂停该队列。
- `REVIEW_FEEDBACK` 处理审核和用户失效反馈。

招聘季、开放岗位、学生关注和历史投递信号会将检查频率提高到每日或每两日；
普通确认入口每周；`NO_OPENINGS` 每两周；`BLOCKED` 指数退避。

## 一天 Canary

```powershell
npm.cmd run monitor:canary:one-day -- `
  --database data/lite-job-search.sqlite `
  --target-count 250 `
  --duration-hours 24 `
  --cycle-minutes 30
```

Canary 对公司去重，每家公司选择一个最高优先级的已验证入口。状态保存在
`output/monitoring-network/one-day-canary/status.json`，结束后写
`final-report.json`。指标定义：

- 入口检查成功率：`SUCCESS + NOT_MODIFIED + NO_OPENINGS` / 尝试检查数；
- 岗位变化发现率：出现发现、更新、关闭或重开 Revision 的公司数 /
  成功检查的公司数；
- 浏览器兜底率：Browser Observation / 尝试检查数；
- 可投递率：已发布 A/B 级活动岗位 / Canary 公司当前岗位数。

若已验证入口不足 200 家，报告必须写出 `shortage`，不能用未验证候选补数。
